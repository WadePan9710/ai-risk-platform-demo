# 面试讲解稿

## 30 秒版本

这个项目不是聊天机器人外壳，也不是拆成多个页面的展示站，而是一个统一的风险策略 Agent 工作台。底层 KPI、特征、血缘、模型、案件和知识检索全部是确定性工具，LangGraph 负责跨域路由、工具取证和人工审批，LangChain 只负责可选的自然语言表达。

## 架构选择

### 为什么用 LangGraph

风险分析不是单轮问答：要识别组合、特征、血缘、模型、案件或知识意图，调工具、汇总证据、处理写动作审批和恢复。LangGraph 把这些步骤做成显式状态机，可以用 checkpoint 恢复，也能逐节点测试。

### 为什么不用 ReAct 自由循环

风控场景不能让模型自己决定任意工具和数字。当前实现使用固定工具白名单，模型只看到已经计算好的 findings。这样可以明确区分“计算事实”和“语言表达”。

### 为什么保留确定性 narrator

Demo 在没有 API Key 时也必须可运行，同时方便测试。LLM 不可用不能影响指标和审批流程。

## 关键工程点

1. FastAPI 同时提供统一 API、工作台页面和八个业务模块，部署只有一个 Python 进程。
2. SQLite checkpointer 支持暂停和恢复。
3. `interrupt()` 把写动作放进人工审批，批准前不会执行。
4. 每个回答带工具名、`call_id` 和结构化 evidence。
5. 统计与规则质量有自动化测试。
6. 特征和血缘模块不是静态占位：特征目录、开发任务、IV/KS/PSI 和血缘边都由确定性数据驱动。
7. 知识模块与业务模块共用同一个 Agent，不是第二个聊天入口。

## 可以展开讨论的边界

- 当前使用合成数据，真实版本应接只读数据网关。
- Demo 的 action ledger 在内存中，真实版本应落数据库和审计表。
- 当前 API 无身份系统，真实版本需接入 SSO、RBAC 和租户隔离。
- 规则质量是相关性信号，不是因果结论。
